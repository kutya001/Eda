# Шаблон-каркас приложения

Готовый каркас для нового приложения с тем же интерфейсом, что у прототипа Buhuchet.kg: один и тот же код работает на ПК и на телефоне, общие компоненты (таблица, карточка, форма, главная) уже собраны. Правила, на которых он построен, описаны в документе «Основные паттерны разработки». Номера разделов ниже взяты из него.

Обычный HTML, CSS и JS, без npm и без сборщиков. Python нужен только для `build.py`.

## Как запустить

- **Из папки.** Запустите `python3 -m http.server` в папке `template/` и откройте `http://localhost:8000/`. Данные читаются из `data/*.json`.
- **Одним файлом.** Выполните `python3 build.py` и получите `dist/prototype.html`, где все стили, скрипты и JSON внутри. Его можно открыть двойным щелчком, отправить файлом или опубликовать.
- **GitHub Pages.** Положите папку в репозиторий и включите Pages. `index.html` работает как есть.

В боковой панели (на телефоне в «≡ Другие модули») есть блок «Прототип»:

- «Данные: Демо-данные / Пустая организация»;
- «Войти как» (владелец, руководитель, сотрудник, заблокированный, администратор платформы);
- экспорт и загрузка рабочих данных `TemDB.json`;
- «Очистить рабочие данные»;
- экспорт `refDB.json`.

## С чего начать новое приложение

1. Скопируйте папку `template/` в новый репозиторий.
2. В `src/js/core/config.js` задайте название, префикс ключей в браузере, валюту и часовой пояс. Там же выберите 4 модуля нижней панели телефона.
3. В `index.html` поменяйте `<title>` и ключ темы `app.theme` на `<префикс>.theme`.
4. Замените примеры модулей «Клиенты» и «Заявки» своими сущностями. Остальные модули («Главная», «Сотрудники», «Справочники», «Моя организация», «Журнал», админка) обычно нужно только переименовать и подправить.
5. Перенесите данные в `data/*.json`. В коде данных нет.

## Как добавить модуль

1. Создайте файл `src/js/modules/<модуль>.js` с функциями `<x>Tabs()`, `<x>Add()`, `render<X>(body, tab, fresh)`. Список строится через `grid(host, cfg)`, карточка через `openModal({size:'wide', live:true, …})`.
2. Подключите файл в `index.html` перед `core/registry.js`. `build.py` берёт тот же порядок.
3. Добавьте описание модуля в `BIZ` в `core/registry.js`: `id, title, short, icon, desc, perm, feature, tabs, add, badge, empty, render`.
4. В `data/refDB.json`:
   - добавьте группу прав в `permissions` (право просмотра идёт первым, `scope: true`, если нужно «Свои / Все»);
   - если модуль можно выключать, добавьте функцию в `features`;
   - если есть статусы, добавьте шкалу в `statuses`;
   - если нужны списки, добавьте справочники в `dictionaries`.
5. Добавьте ключ данных в `DB_ORG_KEYS` в `core/data.js` и массив в `demoDB.json` и `TemDB.json`.
6. Если у записей есть статусы, используйте `scaleFull / bindScale / rollbackDlg` из `ui/status.js`. Все изменения записывайте через `log()`.

## Чего в шаблоне нет

- Обучения «Показать как», уроков и базы знаний. Остался только крючок `track()` в `utils.js` и окно помощи «?» с описанием модуля. Если они нужны, их можно перенести из прототипа Buhuchet.kg (`tour.js`, `kb-*.js`).
- Telegram-бота, календаря, денег и показателей. Это модули предметной области, их удобнее добавлять по образцу `clients.js`.
- Сервера. Шаблон служит макетом и спецификацией. Продукт пишется отдельно (раздел 22 документа).
