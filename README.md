# Eda — макет приложения учёта для столовых и доставки питания

Кликабельный макет мультитенантного приложения для организаций общепита: столовых и кухонь, которые готовят комплексные обеды и развозят их заказчикам. Макет собран по ТЗ [`docs/ТЗ Eda (итоговое).md`](docs/ТЗ%20Eda%20(итоговое).md) и совпадает с ним: каждый модуль, поле, статус и право из ТЗ есть в макете.

Это макет, а не продукт: сервера нет, данные демонстрационные и живут в браузере. Каркас — шаблон прототипа Buhuchet.kg, правила описаны в документе «Основные паттерны разработки». Обычный HTML, CSS и JS, без npm и без сборщиков. Python нужен только для `build.py` и `tools/make_data.py`.

## Как запустить

- **Одним файлом.** Откройте `dist/prototype.html` двойным щелчком. Внутри все стили, скрипты и данные. Пересобрать: `python3 build.py`.
- **Из папки.** Запустите `python3 -m http.server` в корне репозитория и откройте `http://localhost:8000/`. Данные читаются из `data/*.json`.
- **GitHub Pages.** Включите Pages для репозитория, `index.html` работает как есть.

## Как смотреть макет

В боковой панели (на телефоне в «≡ Другие модули») есть блок «Прототип»:

- «Войти как»: все сотрудники двух демо-организаций по ролям («Владелец», «Управляющий», «Шеф-повар», «Повар», «Кладовщик», «Курьер», «Бухгалтер»), представители заказчиков и «Администратор платформы». Алиева А. (бухгалтер) состоит в обеих организациях, у неё есть переключатель «Организация»;
- «Данные: Демо-данные / Пустая организация» (как сразу после регистрации);
- «Показать ошибку загрузки списка»;
- экспорт и загрузка рабочих данных `TemDB.json`, «Очистить рабочие данные», экспорт `refDB.json`.

Демо-данные сдвигаются так, что «сегодня» в макете всегда сегодня. Всё, что вы меняете, сохраняется в этом браузере. Что стоит попробовать:

- управляющим (Токтогулов Б.) на телефоне: «+» на «Главной» → «Быстрый заказ»: новый номер и имя, адрес в «БЦ «Аврора»», позиции, «Мобильный кошелёк» с чеком («Демо: подставить чек»); затем найти клиента по последним цифрам номера во вкладке «Заказчики → Физлица»;
- «Доставка → Карта»: места скопления (бизнес-центры) одним маркером, панель места и «Добавить в рейс»; «Кухня → Требование»: сколько чего приготовить и на какие точки;
- курьером (Касымов А.) на телефоне: модуль «Маршрут», переключатель «Сеть есть / Нет сети», отметки «Доставлено» с фото, «Сдать наличные»;
- представителем заказчика (Петрова Е.): «Заказать» на ближайшую дату с открытым меню;
- поваром: в заказах и техкартах нет цен и сумм, модуля «Деньги» нет;
- владельцем: «Моя организация → Учётная политика», выключить «Доставка»;
- администратором платформы: «Организации → Приостановить», затем войти сотрудником этой организации.

## Как менять макет

Порядок всегда один: сначала правка в ТЗ, потом в макете.

- **Данные.** Правьте `tools/make_data.py` и запускайте `python3 tools/make_data.py`: демо-данные согласованы между собой (списания по техкартам, остатки, накладные, оплаты и долги считаются по тем же правилам, что и в макете). Затем `python3 build.py`.
- **Новый модуль.** Файл `src/js/modules/<модуль>.js` с функциями `<x>Tabs()`, `<x>Add()`, `render<X>(body, tab, fresh)`; подключить в `index.html` перед `core/registry.js`; описать в `BIZ` в `core/registry.js`; права, функции и шкалы — в `tools/make_data.py` (раздел `refDB.json`).
- **Статусы** — только через `setStatus()` и шкалу из `ui/status.js`; последствия переходов — в `SC_AFTER`, запреты — в `SC_WHY`.
- **Изменения записей** — через `log()`: они попадают в историю записи и в «Журнал изменений».
